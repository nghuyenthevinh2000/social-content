# Backend Profiling & Optimization Plan

```text
profiling.py --context {db|http|supervisor|worker|video|all} -> Isolated Context Runner -> Span / SQL / Blob / RSS Table -> Fix -> Re-run Single Context
```

## 1. Profiling Strategy & Centralized Module (`profiling.py`)

| Dimension | Decision | Rationale |
|---|---|---|
| Centralized module | Create `tools/app/backend/profiling.py` as the single stdlib-only profiling module (`time.perf_counter`, `contextvars`, `resource`, `tracemalloc`, `cProfile`, `pstats`) gated by `PROFILE_BACKEND=1`. | Follows `ponytail` stdlib-first ladder; keeps timing, SQL/S3 counting, memory tracking, and benchmark reporting in one file instead of scattering ad-hoc timers across modules. |
| Selective context execution | Support `--context {db,http,supervisor,worker,video,all}` (comma-separated) on `python3 tools/app/backend/profiling.py` and `PROFILE_CONTEXTS` env filtering at runtime. | Enables sub-second isolated runs of a single subsystem (e.g., `db` or `http`) during iterative optimization without waiting on slow workers, S3 transfers, or video generation. |
| Core primitives in `profiling.py` | Expose `span(category, name, **meta)`, `request_scope(method, path)`, `record_sql(query, ms)`, `record_blob(op, key, bytes_len, ms)`, `rss_kb()`, and per-context benchmark runners (`run_context(name)`). | Gives HTTP threads, worker processes, and quick CLI benchmarks a uniform API with near-zero overhead (`if not ENABLED: yield; return`) when disabled. |
| Primary metrics | Capture p50/p95/p99 latency (ms), SQL query count + lock wait time (ms), S3/RustFS transfer latency + RSS memory delta (MB), and subprocess wall time (s). | Separates Python CPU/GIL overhead from PostgreSQL row-lock contention, S3 I/O, and external API latency. |

## 3. Identified Bottlenecks & Profiling Targets

| Subsystem & Context | Location & Observed Pattern | Bottleneck / Risk | Profiling Metric & Optimization Opportunity |
|---|---|---|---|
| Job status polling (`db`, `http`) | [store.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/store.py#L136-L214): `JobStore.snapshot()` runs on every `GET /api/jobs/<id>` and triggers `blobs.get("runs/<id>/result.json")`, `fetch_top_reels_transcripts()`, and `UPDATE jobs SET data = %s` when any topic lacks a transcript. | Synchronous S3 download, external transcript scraping, and DB write lock inside a read-only HTTP poll path. | Measure `snapshot()` wall time vs. DB-only read via `profiling.span`; move enrichment strictly to worker completion in [research.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/research_engine/research.py#L428-L457). |
| Per-request auth hook (`http`) | [server.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/server.py#L153-L192): `Handler._user_id()` runs `CREDIT_STORE.claim_email_credits()` (`SELECT ... FOR UPDATE`) and legacy `UPDATE topics` / `UPDATE jobs` on every authenticated API request. | Unnecessary write transactions and row locks on every `GET` request. | Count SQL statements per HTTP request in `profiling.request_scope`; gate legacy/email claims behind an in-memory `set` of seen `(uid, email)` pairs per process. |
| Worker supervisor loop (`supervisor`) | [handler.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/handler.py#L75-L105): Every `1.0s`, `run_worker()` calls `STORE.heartbeat()` (1 `UPDATE` per job) and `STORE.snapshot(job_id)` (full JSONB + 400 log rows + enrichment) for each running job just to read `cancel_requested` and `pid`. | High polling amplification and JSONB deserialization every second. | Measure queries/tick in `--context supervisor`; batch heartbeats with `WHERE id = ANY(%s)` and query `data->>'cancel_requested', data->>'pid'` directly. |
| Job history listing (`db`, `http`) | [store.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/store.py#L228-L274): `JobStore.list_jobs()` fetches up to 500 full `data` JSONB blobs (`SELECT data FROM jobs ... LIMIT 500`) and parses all nested sheets/topics in Python. | Large network payload from Postgres and high CPU/memory allocation per `/api/jobs` call. | Measure payload bytes and serialization ms in `--context db`; project summary fields in SQL (`jsonb_array_length`) or store summary keys at write time. |
| JSONB full-row lock (`db`, `worker`) | [store.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/store.py#L31-L41): `JobStore._mutate()` locks the row (`FOR UPDATE`), loads the full `data` JSON, mutates in Python, and rewrites the entire JSONB blob on every `patch_sheet` / `update`. | Write amplification and lock contention between worker updates and API reads. | Measure `_mutate()` lock hold time; use `jsonb_set` for scalar status updates. |
| Topic library N+1 (`db`, `http`) | [profiles.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/profiles.py#L375-L401): `SocialProfileStore.list_topics()` queries `topics`, then executes a separate `SELECT ... FROM profiles` inside a Python loop for every topic (`1 + N` queries) plus `_ensure_seeds()`. | Latency scales linearly with topic count on `GET /api/sources/topics`. | Count queries per call in `--context db`; replace with a single `LEFT JOIN` or `WHERE topic_slug = ANY(%s)` query. |
| ACP global serialization (`worker`) | [research.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/research_engine/research.py#L135-L152) & [acp.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/acp.py#L42-L53): `_harness_lock` holds a global Postgres advisory lock across all workers, and `ACPClient` spawns a cold CLI process (`initialize` + `new_session`) on every prompt call. | Serializes all multi-worker jobs and adds cold-start overhead (`npx`/`agy`) to keyword expansion, visual analysis, and topic generation. | Log `acp_lock_wait` vs. `acp_prompt` duration in `--context worker`; reuse a warm `ACPClient` session per sheet/job and replace global lock with a bounded semaphore or per-agent lock. |
| Keyword search fan-out (`worker`) | [video_search.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/research_engine/video_search.py#L458-L468): `run_viral_video_search()` executes `3 queries × 5 platforms = 15` `glasser run` subprocesses strictly sequentially (up to `15 × 45s`). | Worst-case 675s blocking wall time on I/O-bound CLI calls. | Time per-platform `search_platform()` spans in `--context worker`; parallelize the 15 calls with `ThreadPoolExecutor(max_workers=5)`. |
| Media & video serving (`http`, `video`) | [server.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/server.py#L310-L320) & [server.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/server.py#L437-L450): `blobs.get()` loads entire MP4/image files into RAM and sends `Accept-Ranges: bytes` without handling `Range` requests. | High peak RSS memory under concurrent video playback and broken browser byte-seeking. | Track RSS delta in `--context http`; stream chunks or serve HTTP 206 `Range` slices / presigned URLs. |
| Health & log endpoints (`http`) | [server.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/server.py#L79-L93) & [server.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/server.py#L199-L229): `/api/health` runs uncached Glasser/import checks every 30s; `/api/logs` reads the entire log file into RAM before slicing `[-65536:]`. | Disk I/O spikes and memory spikes as `AIBrand.log` grows. | Cache `/api/health` probes with a 30s TTL; seek to `max(0, size - 65536)` in `/api/logs`. |
| Local ASR & `.env` reload (`worker`, `video`) | [reel_research.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/research_engine/reel_research.py#L738) & [video_engine.py](file:///Users/thevinhnguyen/Documents/computer-science/projects/social-content/tools/app/backend/video_engine.py#L29-L38): `_transcribe_local_fallback()` instantiates `UnifiedTranscriber()` per reel; `_load_env()` re-reads `.env` from disk on every duration/rate check. | Repeated model weight loading in worker processes and redundant disk reads. | Cache singleton `UnifiedTranscriber` per worker process; run `_load_env()` once with `@functools.lru_cache(maxsize=1)`. |
